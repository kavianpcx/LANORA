# LANORA 0.2.0-alpha.7

Experimental update for the connected dashboard, profile synchronization, and profile/onboarding dialogs.

- Hide the disconnected server form after a successful join. The connected view now prioritizes the server address, measured API round-trip time, virtual IP, and player list.
- Show each authorized player's selected avatar and display name to other members. Profile updates use the existing authenticated membership token and refresh through the current polling path.
- Label server latency separately from EasyTier peer latency. Show only peer-route, latency, and direct/relay data reported by the native EasyTier status command; expire stale readings and never assign a peer ping to yourself.
- Track presence refresh freshness and report server interruption without stopping a still-running tunnel. Authorization rejection continues to stop and revoke the active client session.
- Retry a bounded number of times after an unexpected EasyTier process exit. Invalid addresses and failed player authorization are not retried automatically.
- Rotate room network credentials after a host removes a member; current authorized room clients observe the new generation and retrieve the rotated configuration.
- Add a redacted connection-diagnostics panel and an authenticated `bash scripts/server.sh doctor` report for local service checks.
- Keep profile dialogs viewport-bounded, with a persistent header and footer, compact six-avatar preview, optional full picker, and the existing artwork and avatar identifiers.
- Keep Persian structural layout LTR while applying RTL to translated text and isolating technical values.

The release remains experimental. API and isolated namespace checks do not establish Windows-to-Windows connectivity, external relay reachability, direct P2P/NAT traversal, game-specific LAN discovery, or immediate removal of a modified client already holding an EasyTier secret. These items must be reported against the actual release workflow and test environment.
