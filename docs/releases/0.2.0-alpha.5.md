# LANORA 0.2.0-alpha.5

This experimental prerelease makes the player password optional for self-hosted servers.

## Player connection

- The desktop checks the server's public connection information before joining.
- Passwordless servers connect without a password prompt.
- Protected servers show a password dialog with show/hide and retry controls.
- Older alpha servers that lack connection discovery continue to use their existing access-code prompt.
- Public-server HTTPS validation remains enabled; plain HTTP is still limited to localhost.

## Server owner

- Fresh server setup asks whether players must use a password. Yes is the default and recommended for public servers.
- Player passwords are stored as PBKDF2-SHA256 hashes. The installer hides password input and confirms it before enabling protection.
- `bash scripts/server.sh player-auth status|enable|change|disable` checks or changes policy without reinstalling.
- Existing installations keep their player protection. Legacy environment access codes migrate into SQLite; existing `.env` settings and database contents are preserved.
- Policy changes revoke API sessions and rotate the current EasyTier network identity. This cannot force a modified client with the old secret to leave its running overlay; ask players to disconnect and rejoin.

## Security

Passwordless mode opens player joins to anyone who can reach the server. Administrator authentication, internal EasyTier relay credentials, and protected admin endpoints remain separate. Discovery returns only the policy and API version; join authorization is still enforced by the API.

## Verification scope

CI validates API behavior and password-policy changes, server command contracts, desktop policy discovery, and release builds. The isolated Linux EasyTier relay test does not establish that two independent public networks, Windows game traffic, direct P2P, or game-specific LAN discovery work. Check the workflow attached to this release for the exact job results.
